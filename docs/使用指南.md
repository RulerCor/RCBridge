# RCBridge 使用与构建指南

## 开始使用

1. Windows x64，需已安装 Microsoft Edge WebView2 Runtime。完整解压便携包，运行顶层的 `RCBridge.exe`，不要只移动 EXE。Python 和桥接依赖已随包提供。微信、WeRC、WeFlow、Alpha 和 AstrBot **均不随包安装**。
2. 在已连接微信的 WeRC 桌面端选择「Bot 接入」，复制授权配置。在 RCBridge「连接设置 → 从 WeRC 导入 Bot 接入配置」粘贴 JSON，点击「填入连接设置」。也可手动填写本机地址、账号 ID 和令牌。**只读测试连接**不保存、不发送、不批准任务。
3. 填写下游 OneBot v11 应用的反向 WebSocket 服务地址及可选访问令牌。通用模式不要求安装 AstrBot；机器人逻辑、模型和命令由下游实现。要同步成员权限、会话风格并从面板重启 AstrBot，还需填写现有 AstrBot 的 `data/cmd_config.json` 绝对路径；本地附件发送请配置 AstrBot 附件目录。保存后**关闭并重新打开整个 RCBridge 窗口**，再点「启动桥接」。仅点停止/启动不重新加载进程级配置。
4. 在总览确认「接收接口已连接」及「OneBot 已连接」。两项均不等同于真实消息送达。首次使用建议先与专门的测试联系人验证。关闭窗口即结束专属桥接服务，不会关闭微信、WeRC 或 AstrBot。

### 从旧面板迁移

不覆盖旧配置，不自动导入聊天记录、联系人、白名单或凭据。接收端可选 **WeRC / Alpha / WeFlow**，发送端可独立选 **WeRC / Windows UIA / Alpha API**。不要让新旧桥接同时接管同一微信账号和同一 AstrBot 平台，以免重复处理。沿用同一 AstrBot 配置后，保存成员与权限会修改该配置；这与只读测试不同。

| 工作区 | 保留和新增的操作 |
| --- | --- |
| 运行总览 | 启动/停止、暂停/恢复接收、群标准/批处理、OneBot/消息源状态、日志、运行时长、退出原因与历史；手动只读查询 WeRC 发件箱最近 25 条任务状态 |
| 连接设置 | 接收与发送方式、WeRC 导入/探测、机器人身份与昵称、自动检测、缓冲、引用/@、图片与描述模型、后端地址令牌、AstrBot 与附件路径、UIA 切换、日志及旧版兼容字段，支持搜索 |
| 群聊 | 单群回复开关、随机插话设置与作用范围、群列表刷新/检索，保存 AstrBot 设置与重启 |
| 私聊 / 管理员 | 好友检索、私聊白名单与总开关、管理员选择与同步；不将群会话 ID 充当成员身份 |
| 会话风格 | 按会话指定 Humanizer 档案、只看自定义或跟随全局；档案由原插件提供，需要已配置对应 AstrBot |

### WeRC 行为约定

- 仅接受本机回环地址，令牌只发在 `Authorization` 请求头，不走系统代理，不跟随重定向。桌面控制端同样只绑定回环；默认 18766，需要本次桌面进程产生的会话密钥。**不支持旧面板的裸局域网访问。**
- 首次启动用 `GET /api/v1/messages/native?after=-1&limit=1` 取最新游标作为起点；随后订阅 `/api/v1/messages/native/stream`。原生 `message.received` 才进入 OneBot。临时断线用 `Last-Event-ID` 接续，同轮重复位置跳过。显式停止或退出后重新启动只处理新消息，不补发停机期间的历史；`receive.status` 的缺口不是历史完整性保证。
- 只转发账号一致、方向明确的 schema 3 入站消息，自发和缺少方向的旧记录跳过。私聊用精确 username；群信封只能确定会话，不能证明是哪位群成员。未标识成员使用会话专属匿名身份，不套用个人管理员权限。WeRC 联系人列表来自已导入的联系人快照，不凭昵称检索发送对象。
- 入站支持正文、可解析卡片文本、可获取的原生图片。语音/视频等观测不伪装成文字或可播放内容。WeRC 发送支持 OneBot 文本、图片、文件、视频、语音（WeRC 接受的音频格式）；媒体先上传再提交，限 8 MiB。本地文件必须位于配置的附件目录，亦支持 `base64://`。不从网络地址代下载。WeRC 路径不是 UIA：不模拟原生引用或原生 @；可按开关转为文字。需要旧原生引用交互时选择 UIA。
- 每次提交携带幂等键。不自动重试、不把图片失败降级成文件。未知、被拒绝或部分成功时先查回执。「排队/待批准」返回 OneBot `async`，不声称已送达。`server_accepted` 与 `recipient_confirmed` 是不同的证据。发件箱仅手动读取，不提交、撤回或重放。
- 直接向未识别的 OneBot 数字 ID 发送会失败：需先建立入站微信会话映射，不把数字或同名联系人猜成目标。`events/stream` 属于产品/任务事件，不能当作微信消息流；RCBridge 不需要 MCP。

### 数据、权限与问题定位

用户资料位于 `%LOCALAPPDATA%\RCBridge`。`config.json` 保存本机配置（含明文授权令牌），`data` 存成员与诊断，`bridge.log` 可能含消息内容，`WebView2` 是桌面浏览器资料。不要共享整个用户资料目录；泄露令牌可在 WeRC 撤销并重新签发。程序不会从剪贴板自动取授权，也不默认启动消息桥接。

- **401/403**：核对授权账号、令牌是否已撤销以及所需权限。接收需 `messages:read` 和账号范围；名册需 `contacts:read`；读取回执需 `operations:read`。不同发送类型另需对应权限和 `operations:create`，自动批准取决于 `messages:execute`。
- **列表为空**：先区分联系人快照是否已导入、是否有新的原生入站消息、是否仅缺少群成员身份。消息 API 可读不等于微信原生连接就绪。
- **面板收到了消息但机器人不回**：先看 OneBot 连接、群静音及 AstrBot 白名单。白名单保存后需重启 AstrBot；WeRC 与 OneBot 均在线仍不能证明模型可用。
- **打开即提示控制服务未就绪**：检查是否已开另一个窗口、18766 或配置端口是否被占用。不要杀死占用端口的其他服务；在本程序配置里改用空闲端口。界面未打开时也可先备份自己的 `config.json` 再更正。

## 维护与验证

源码位于 `desktop/`（窗口、桌面 HTTP 服务、界面与系列图标）、`bridge/`（消息源、收发器、OneBot、可选 AstrBot 管理）、`tests/`。`build_desktop.py` 只从本项目及所选 Python 环境组装发行包。`toolchain/` 是本机已准备的可移动 Python 与 WebView2 SDK 缓存，可离线构建；不随 Git 提交。版号以 `bridge/VERSION` 为准；[变更记录](../CHANGELOG.md)记录各版本内容，[版号与存档](版号与存档.md)说明如何归档、核验与回退。项目继承的桥接代码保留原 MIT 许可，见 LICENSE。

在本项目根目录执行（PowerShell；输出目录须不存在）：

```powershell
./toolchain/python/python.exe -X utf8 -m unittest discover -s tests
./toolchain/python/python.exe -X utf8 build_desktop.py build/smoke-win-x64
./toolchain/python/python.exe -X utf8 tests/offline_roundtrip.py build/smoke-win-x64
```

从纯源码重建：准备 Windows x64 CPython 3.13 和 .NET Framework 4.x 的 x64 C# 编译器；用 `py -3.13 -m venv .venv` 创建环境，运行 `.venv/Scripts/python.exe -m pip install -r requirements-lock.txt`，再用该解释器执行以上命令。缺少 WebView2 绑定缓存时，构建器通过 pip 下载固定版本 wheel 并核验摘要。

### 旧用户配置

首次启动使用 `%LOCALAPPDATA%\RCBridge`，不会自动读取旧令牌。如要保留旧设置，关闭两个版本，备份后将原 `%LOCALAPPDATA%\RC_Mon3trBot\RCBridge` 中的 `config.json` 和需要的 `data` 复制到新资料目录；不必迁移 WebView2 缓存。旧 `astrbot_ob_url` 仍可读取，保存新设置后使用 `onebot_ws_url`。想使用通用模式，请清空 AstrBot 主配置路径；只有显式配置后才开放其专属操作。

### 验证边界

自动测试使用隔离的本地模拟 WeRC 和 OneBot 服务端，不触发真实微信外发。拆分前已完成本机 WeRC 接口的只读联调；本次迁移重新验证独立构建、契约测试与模拟收发，不等于每个第三方机器人框架都已经实机认证。
